# Решения проекта

Решения, которые касаются нескольких подрепозиториев: состав, контракты между ними, версии, сборка, выкладка. Устройство внутри репозитория — ADR этого репозитория. Решения директора — в штабе (D-…).

Формат: **P-номер — суть.** Дата. Статус (предложено / принято / заменено). Почему. Что следует.

---

**P-001 — Подрепозитории перечисляются в `repos.yaml`, а не git submodules.** 2026-10-03. Принято (D-002).
Подмодули легко ломаются: оторванный HEAD, забытый `--recursive`, коммит в подмодуле, не попавший сюда. Файл с версиями даёт то же — какая версия чего собрана — и читается глазами.
Следует: `make sync` разворачивает `repos/`; поле `version` — ветка или тег для сборки.

**P-002 — `bhendho` — ядро, контракты и SDK вместе.** 2026-10-03. Предложено, ждёт директора.
Контракты описывают API ядра, SDK — клиент этого API. Если держать их отдельно, каждое изменение API — три согласованных PR в трёх репозиториях. Вместе — один PR и одна версия.
Модули платформы (алгоритмы, склад, тьюторы, сказки) и фронты в `bhendho` не входят: они уходят в свои репозитории (G-004).
Следует: G-002 переносит в `bhendho` `cmd/`, `internal/core/`, `contracts/`, `pkg/sdk/`.
